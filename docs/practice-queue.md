# Practice 持久队列

每个学习者、Topic、Example 共用一条长期题目队列。Lesson 和复习从同一队列取题，FSRS 仍以 Example 为单位决定下次推送时间。

## 算法

1. 新 Lesson 的前 3 道普通练习固定取前三组首题（展平后的第 1、4、7 题），按顺序展示。首次创建长期队列时以这三题起步。若已有队列，保留其他待推送题和展示记录。复习独立初始化队列时，五组各随机首抽一题。
2. 实际展示下一题时，从队首取出；本轮已展示题跳过并保留到下一轮，确保同轮不重复。只看历史、刷新或重复请求不取新题。
3. 本轮第一次答错追加 1 道，后续答错每次追加 2 道。某组首次判错时优先选该组可用的其他题，随后按未推送、最久未推送的次序选题。跳过已排队、本轮已展示或本轮已指定的练习。组内首次补题的标记跨 Lesson、复习、暂停和解锁保留。Lesson 第 4 次错立即暂停，此次不再补题。复习第 3 次错后暂停，此次补题留待之后的复习。
4. 队列没有本轮可用题时，随机选一道未推送、未排队且本轮没出现过的题；全部推送过后，选最后一次推送最早的题。
5. 每轮只按当前题量需求取题。轮次结束不清空队列；下次到期继续。

实际作答的例题在判定后入队供复习，每道例题在同一队列中最多保留一个待推送位置。直接答对仍可完成模块，直接答错计为本轮第一次错误。「未掌握」后选择「尝试完成」时，例题计为第一道练习。例题没有练习分组，答错时从同模块选取补题。本轮仅推送例题一次，它在后续复习中按队列顺序参与作答和评分。

“推送”指实际展示题目，不是预先放入队列。展示后主动暂停、未作答，也算已推送；不会因此记错。先入队的补题保持队列顺序，补题规则可使此前见过的同组题早于未见题再次出现；未见优先和最久未见优先用于队列不足时的补充。

最久未推送以递增展示序号比较，不依赖系统时钟。一个题目每次实际展示都会更新序号，因此连续复用时不会一直选择第一次做过的同一题。

例如新 Lesson 先排 `[1.1, 2.1, 3.1]`。`1.1` 答错时，将 `1.2` 放到队尾，本轮目标由 3 增至 4。若后续再错，目标依次增至 6、8。

## 题源与单轮评分分开

| 场景 | 本轮累计错误数 | 本轮目标题量 | 完成后评分 |
|---|---|---|---|
| 新 Lesson（15 题分组库） | 0 / 1 / 2 / 3 | 3 / 4 / 6 / 8 | 4 / 3 / 2 / 1 |
| 新 Lesson（未分组旧库） | 0 / 1 / 2 / 3 | 2 / 3 / 5 / 7 | 4 / 3 / 2 / 1 |
| 新复习 | 0 / 1 / 2 | 1 / 2 / 4 | 4 / 2 / 1 |

Lesson 第 4 次错、复习第 3 次错或主动暂停均沿用 Topic 暂停机制，本轮没有评分。题量和队列追加量共用 `practice.py` 的轮次策略。

## 数据与兼容

- `practice_queues` 按 `learner + topic + module` 隔离，保存课程版本、队列、已补题组和展示顺序；不通过公开接口返回未来题或队列。
- 队列继续使用 `practice_queue_version=grouped-v1`。新轮次保存 `lesson-v3`、`lesson-v3-sequential` 或 `review-v2` 策略快照。旧轮次沿用保存的策略，没有快照的 Lesson 按 `lesson-v1` 继续。取题、保存当前页面和错误补题共用 SQLite 事务。判题失败、重复提交、过期或已暂停轮次的迟到结果不补题。
- `source_practice.group/member` 优先作为分组依据；没有分组元数据的 15 题旧库按原顺序每三题一组。其它合法旧题库的 Lesson 保留练习顺序，复习在例题入队后开始使用持久队列；部分或错误分组元数据拒绝加载。
- 升级前已开始的 Lesson/复习不改变题序，待新轮次采用新机制；不推断或回填旧历史。课程和队列规则版本不符时保留原数据并拒绝操作。
- 暂停、解锁、重启和整库备份保留队列。主动清空某个 Topic 的学习记录会同时清空该学习者的队列和组内补题标记，不影响其他身份。
